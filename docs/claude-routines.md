# Claude の定期実行（Routine）設定メモ

このリポジトリのコードではなく、**開発者アカウント側の運用設定**の記録です。
「なぜ毎朝5時に無人の Claude セッションが1本立つのか」と「その止め方」を残しておくためのメモで、
PWA の動作には一切関係しません。

## 目的：5時間ウィンドウを朝のうちに開始させる

Claude の利用上限は「最初のメッセージを送った時刻から5時間」のローリングウィンドウで区切られます。
日中に作業を始めるとその時刻から枠が切られてしまうため、**未明のうちに極小のメッセージを1回だけ
投げてウィンドウを開始させて**います。

5:03 に開いた枠は 10:00 ちょうどに閉じるので、9時始業なら**始業1時間後にきれいに次の枠へ
切り替わり**、午前中の作業を丸ごと新しい枠で使えます。

## 設定内容

| 項目 | 値 |
| --- | --- |
| trigger_id | `trig_01LgpNeeeAjphdmRVTQw8C1L` |
| 名前 | 5時間ウィンドウ起動（毎朝5時） |
| cron | `3 20 * * *`（**UTC 評価**。日本時間 5:03 は前日 20:03。日本は DST が無いので通年ずれない） |
| 発火のしかた | `create_new_session_on_fire: true`（毎回まっさらな新規セッションを1本） |
| 環境 | `env_016pn7y1P3R5DTT4ETVjY2RJ`（Default） |
| 通知 | push・メールとも off |
| プロンプト | `ok とだけ返して終了。ツールもファイル読み込みも一切しない。` |

分を `:00` にしていないのは、世界中の同種のスケジュールが毎時ちょうどに集中するためです。

### なぜ「新規セッション・リポジトリ無し」なのか

- 既存セッションに紐づけると毎朝そのセッションの会話履歴を読み直すことになり、
  「消費を絞る」という狙いと正反対になる。
- リポジトリを付けないので `CLAUDE.md`（約1万トークン）やファイル一覧を読み込まない。
- このトリガーには MCP コネクタが引き継がれていないため、コネクタのツール定義も乗らない。

### 正直な限界

- **「5時間制限が0%のときだけ」という厳密な判定はしていません**。残量を問い合わせる API が無いためです。
  すでにウィンドウが開いている時刻に発火しても新しい枠は始まらないだけなので、実害はありません。
- システムプロンプト相当の固定費はゼロにはできません。ただしウィンドウは「消費量」ではなく
  「最初のメッセージの時刻」で始まるので、目的は達成されます。

## 確認・変更・停止

claude.ai の **Routines** 画面から操作できます。Claude Code のセッション内から扱う場合は
claude-code-remote の MCP ツールを使います。

- 一覧・実行履歴の確認: `list_triggers`（`last_run` の status と `next_run_at` を見る）
- 時刻の変更: `update_trigger` の `cron_expression`
- 一時停止: `update_trigger` の `enabled: false`
- 削除: `delete_trigger`
- スケジュールを待たずに試す: `fire_trigger`

**作り直さず `update_trigger` で直してください**。削除して作り直すと実行履歴が失われます。

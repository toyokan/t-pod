# 見た目・転送量の設計（スタイル・フォント・コントラスト・ボトムナビ・アニメーション・画像）

色・フォント・ボトムナビ・進行中カード・`<img>`・外部リソースを触る前に読む。要点は `AGENTS.md` の「アーキテクチャの要点」。

- **スタイル**: Tailwind Play CDN。アクセント色は `tailwind.config` の `theme.extend.colors.brand`。基準色は CSS 変数 `--brand`（既定 amber、`<style>` の `:root` で定義）で、`brand-50〜800` は `color-mix()` により自動生成。**イベント毎のブランド色は `events/<id>.json` の `eventInfo.brandColor`（メイン1色の16進）で指定** → `applyBrandColor()` が実行時に `--brand` を上書き（濃淡は自動）。会場/ルームのテーマ色は `index.html` の `COLOR` 辞書（`chip`/`dot`/`border`）が `tailwind.config` の `venue.*` パレット（blue/green/violet/coral）を参照。rooms の色キー `blue/green/orange/purple` を `venue-blue/green/coral/violet` にマッピング。動的生成するクラスは `tailwind.config` の `safelist` に保持（新色は両方に追加）。
- **和文の字面（本文フォント）**: 本文は **Zen Kaku Gothic New**（Google Fonts。吹き出しだけ DotGothic16）。**読み込むウェイトは 400/500/700/900 の 4 種から増やさない**——和文は unicode-range で 100 以上のサブセットに割れるので 1 ウェイト足すだけで転送量が 25% 増え、`trimRuntime()` の上限にも早く当たる。そのぶん **Tailwind の `fontWeight` は `semibold: 500` / `extrabold: 700` に付け替えてある**（`tailwind.config`）——素のままだと 600/800 は CSS のフォント照合で 700/900 へ吸い寄せられ、`font-semibold`＝`font-bold`・`font-extrabold`＝`font-black` と**見分けが付かなくなる**（4 段のつもりが 3 段になり、10〜13px の和文が 900 で潰れる）。**今の太さを保ちたい箇所は 600/800 を使わず `font-bold` を直接指定する**（ガラスの上の 11px ラベル＝ボトムナビ、ブランド地の上の `#eventSubtitle` がこれ。ここを 500 に落とすと細くて読めない）。**`palt` は見出し（`h1,h2,h3`）だけに掛ける**——本文に掛けると長文で字送りが不均一になって逆に読みにくい。字間は `body` の `letter-spacing: .01em` まで（これ以上広げると「全10プログラム」のような `whitespace-nowrap` の要素がはみ出す）。**`text-rendering: optimizeLegibility` は使わない**——和文は字数が多く、カーニング／合字の照合が会場の非力な端末で高くつくわりに見た目が変わらない。
- **コントラストの制約**: `brandColor` は明るい色（amber・黄）も指定されるため、**ブランド色ベタ塗り＋白文字（`--brand-fg`）を新規に増やさない**（実測 1.5〜4.4:1 で WCAG AA 未達。`updateBrandFg()` の輝度閾値 0.55 は緩く、amber でも「白」を選ぶ）。**ブランド面（`#appHeader` / `.brand-bg` / `.brand-card` / `.grad-pill`）の文字色は `var(--brand-fg)` に従わせる**——白を直書きすると ID セレクタが `text-brand-fg` クラスに勝ち、明るい brandColor でも白のままになる（黄 `#FACD4B` で実測 1.51:1。`tests/test_shell_source.py` が検出する）。強調は**白ピル（淡地）＋ブランド濃色文字**で行い、濃色は **`color-mix(in srgb, var(--brand) 48%, black)`（＝`brand-800` 相当）**を使う（ボトムナビ・日付タブの実装を参照）。**`brand-700`（62%）は文字に使わない**——既定の黄 `#ffd900` では白地に対し 3.55:1 で AA 未達（`brand-800` なら 5.52:1）。**例外はアイコン単体**——非テキストの UI 部品は WCAG 1.4.11 の 3:1 でよいので、色味を立てたいときだけ 62% まで上げてよい（黄 3.55:1 / amber 5.14:1。ボトムナビの選択中アイコンがこれ）。**ラベル文字は必ず 48% のまま**にし、62% をこれ以上明るくしない（黄が 3:1 を割る）。また、**明るいブランド色は淡地（`brand-50`〜`200`）や枠線が白い地から見分けられない**（1.0〜1.7:1）ため、ピルを浮かせるには**グレーのトラック＋白ピル**が要る（日付タブは `bg-slate-200/80`、ボトムナビはカプセル自身の地がトラックを兼ねる）。新しい配色を足すときは、既定の黄 `#ffd900` と amber `#f59e0b` の両方で 4.5:1 以上を実測して確認する（`color-mix` の計算結果は Chrome が `oklab()` 表記で返すことがあるため、canvas に塗って RGB を取るのが確実）。
- **ボトムナビ（iOS 26 Liquid Glass 風の浮いたカプセル）**: `#bottomNav` は**当たり判定を持たない位置決めの器**（`pointer-events-none`）で、実体は中の `#navBar.nav-glass`（`pointer-events-auto`）。画面下端に貼らず左右 `px-3`・下 `--nav-bottom` の余白を取って**浮かせる**ので、本文はカプセルの下と左右を流れる。**下の余白はセーフエリアと `--nav-gap` を足さず、`max()` で大きいほうを採る**——足すと iPhone で 2 つぶん空いて浮きすぎる。さらに `--nav-safe-trim`（0.75rem）でホームインジケータ領域の一部を食い、実測で iPhone 40px → 22px まで下げてある。**`--nav-safe-trim` をこれ以上増やさない**——画面下端からの上スワイプ（ホームへ戻る）と競合する。**ナビの上下位置は `--nav-gap` / `--nav-safe-trim` の 2 つだけで動かす**——`#bottomNav` の `padding-bottom` と `--nav-h` の両方が `--nav-bottom` 経由でここから決まるので、直書きすると 2 箇所がずれる（マスコットと更新トーストが取り残される）。**`--nav-h` はセーフエリアぶんを含む**ので、`#mascot` や `.above-nav` で `env(safe-area-inset-bottom)` を足してはいけない（二重に空く）。**屈折を SVG フィルタで作らない**——`backdrop-filter: url(#…)` は **iOS Safari が非対応**で、主要な閲覧環境である iPhone にだけ効かない表現になる（以前入れていた `#lensGlass` の `feDisplacementMap` はこの理由で撤去）。代わりに**縁だけを残すグラデーションのリング**（`::before` に `padding` ＋ `mask` の xor 合成）と多層グラデーションで光の回り込みを作る。**この `::before` は `@supports ((-webkit-mask-composite: xor) or (mask-composite: exclude))` で必ず囲う**——非対応だと mask が効かずベタ塗りの板になってナビを覆い隠す。**`backdrop-filter` を入れ子にしない**——選択ピル（`.nav-brand-card`）は親の `.nav-glass` の中にあるので、ピルにも置くと背景の合成が 2 回走る。しかもピルは毎フレーム動く（スワイプ追従・スライド）ため、2 回目が指を動かしている間ずっと再実行される。ピルは白 .98〜.86 でほぼ不透明なので見た目の差は**最大 6/255**（濃い背景を真裏に敷いて実測）しかなく、会場の非力な端末には代金だけが残る。**彩度はレンズの「枠」ではなく「レンズ越しの中身」に乗せる**——iOS 26 のタブバーで色がついて見えるのは選択中のアイコンとラベルであって、ピルの縁ではない。縁を虹色にすると枠だけが目立って中身が負けるので、リング（`::before`）は白に色を差す程度に留める。**彩度を CSS で伸ばそうとしない**——`oklch(from … l calc(c * 2) h)` は sRGB の外へ出た分をブラウザが素朴にクリップするため、彩度ではなく**色相がずれる**（実測で既定の黄 18.5°・amber 28.4°。amber は赤へ寄る）。`color-mix(… black)` も sRGB で黒を混ぜるので明度と一緒に彩度まで落ち、濃くはなっても鮮やかにならない。そこで **`applyNavInk()`（`index.html`）が実行時に計算する**——ブランドの色相のまま、白ピル上で下限コントラストを満たす範囲で **sRGB に収まる最大の彩度**を二分探索し、`--nav-ink`（ラベル）/`--nav-ink-icon`（アイコン）に入れる。CSS 側は `var(--nav-ink, color-mix(…))` で受けるので、JS が走る前とブランド色が無いイベントは従来の濃色に落ちる。**彩度の頭打ちは係数ではなく明度で決まる**（暗いほど sRGB に入る C が小さい）ので、コントラスト下限ぎりぎりまで明るくしたところが最も鮮やかになる。アイコンが 3:1、ラベルが 4.5:1 なのでアイコンのほうが濃く出せる。**既定の黄はほぼ頭打ち**（白地の上で鮮やかな黄は成立しない）だが、実際のイベントはいずれも `brandColor` を設定しているので効果は出る（実測: teal `#005860`→`#007c87`、navy `#001f43`→`#006ce1`）。**色収差（シアン／マゼンタの `drop-shadow`）はアイコンにだけ掛ける**——11px のラベルに掛けると「レンズ越し」ではなく印刷の見当ずれに見え、文字自体が読みにくくなる（24px のアイコンは線が太いので分散として読める）。**カプセル自身が「グレーのトラック」を兼ねる**（最下層に `rgba(226,232,240,.76)`）ので、選択ピル（`.nav-brand-card`）は**白ガラス＋ブランド濃色文字**のまま淡いブランド色でも見分けられる。角丸は外 `rounded-full`（≈30px）／内 `rounded-full`（≈24px）で自動的に同心になる。**高さは `:root` の `--nav-h`（カプセル 4.05rem ＋ `--nav-gap`）に集約**し、`#mascot` と `.above-nav`（更新トースト）はここから位置を取るので、**ナビの高さを変えたら `--nav-h` だけ直す**（以前は 5.5rem / `bottom-24` の直書きで、ナビを変えるたびに 2 箇所がずれた）。スワイプの進捗は `#bottomNav` ではなく **`#navBar` の幅**で測る（器は左右の余白ぶん広い）。**`backdrop-filter` のコストは「ぼかしの半径」ではなく「有るか無いか」**——GPU を切って trace を取ると、スクロール 90 フレームのラスタ処理が無し 283ms に対し有り 741ms（2.6 倍）で、半径を 8px まで落としても 9% しか変わらない（非単調でノイズの範囲）。つまり**半径を下げても軽くならない**ので、軽くしたいなら外すこと。非力な端末では head の inline script が `.no-glass` を付けて`prefers-reduced-transparency` と同じ不透明版へ落とす。**判定はメモリとコア数の両方が低いときだけ**にする——コア数はコンテナや省電力で実力より小さく申告されることがあり、片方だけだと十分動く端末から取り上げる。`deviceMemory` は Safari に無いので iPhone は常に対象外（実機でも重くない）。地の不透明度をフォールバック側で戻すときは **`body.is-scrolled .nav-glass`（詳細度 0,2,0）も一緒に打ち消す**——`.nav-glass` だけ不透明にしても後勝ちで透過値が戻り、「ぼかし無しで半透明」といういちばん読めない状態が残る。**地の不透明度は手計算で決めず、実際に描画して測る**——`backdrop-filter` のぼかしが周囲を巻き込むため単純なアルファ合成の計算と合わず、手計算で 4.7:1 と見積もった `.64` は実測 3.94:1（純黒を真裏）で AA を割っていた。現在は静止 `.76`（実測 4.77:1）／スクロール中 `.82`（同 5.18:1）。
- **アニメーション**: 追加してよいのは `transform` / `opacity` のみ（GPU 合成・ビルド工程なしを維持）。タッチ／スクロール系のリスナは **`{ passive: true }` を崩さない**（スワイプは指追従せず「離した時点でコミット」する設計。`index.html` の `TAB_ORDER` とスワイプ IIFE を参照）。新規の演出クラスは `prefers-reduced-motion` ブロックへ必ず追記する（Tailwind の `transition` / `active:scale-*` はこのブロックの対象外なので取りこぼしに注意）。**進行中カードの「回る縁」（`.now-ring`）は角度ではなく `transform` で回す**——`conic-gradient(from var(--angle))` を `@property` で回すと縁を毎フレーム塗り直すことになるので、**リング状に切り抜いた器＋その中で回る大きな四角**（`.now-ring > i`）に分け、回すのは `rotate()` だけにする。中の四角は**幅 140% の正方形**（カードの対角線より大きいので角が覗かない。横長にすると角速度が場所で変わって光の進みがムラになる）。器は `padding` ＋ `mask` の xor 合成でカード枠と同じ 2px の帯だけを残すので、下の `border-brand-500` の上に光だけが重なる（枠が消える瞬間が無い＝進行中の目印は常に読める）。**`inset` は `0` ではなく `-2px`（＝枠幅）にする**——絶対配置の基準はカードの border box ではなく **padding box（枠の内側）**なので、`0` だと光の帯が枠の「上」ではなく「内側」に出て**罫線が二重に見える**。さらに `border-radius: inherit` はカードの外側の半径（16px）なのに padding box の角は 16−2＝14px なので、**角のアールが食い違ってズレる**（実測: リングの箱がカードの border box より左右上下 2px ずつ内側だった）。**一度だけ光る枠（`.is-now::after`）を `prefers-reduced-motion` で `animation: none` にしてはいけない**——止めると `opacity: 1` のまま残り、カードの 3px 外側にもう 1 本の輪が出たままになる（これも二重の罫線）。`display: none` で消すこと。**ナビのリングと同じく `@supports ((-webkit-mask-composite: xor) or (mask-composite: exclude))` で必ず囲う**——非対応だと mask が効かずベタ塗りの板がカードを覆う。**光はブランド色を混ぜた不透明な色で作らない**——`color-mix` の色は枠を「置き換える」ので一周ごとに縁が途切れる（navy `#001f43` で実測、枠そのままの 15.7:1 が光沢のピークで 1.8:1 まで落ちた）。**白と黒の半透明を重ねる**と下の枠の色が必ず残る。**濃さは手計算で決めず、合成後の色を地（`#f8fafc`）と突き合わせて測る**（現在 白 .40 / 黒 .34。光沢のピークで 黄 1.18 / amber 1.52 / coral 1.85 / violet 2.95 / teal 2.97 / navy 4.28）。**白をこれ以上濃くしない**（.70 で navy 1.8・黄 1.07 まで落ちて縁が切れて見える）。陰は逆に枠を濃くするので明るい色ほど効き（黄 1.32→3.04）、**明るい brandColor では陰が、暗い brandColor では光沢が動きを伝える**。見た目の確認は `dev/now-card.html`（ブランド色・`no-glass` を切り替えて並べる）。非力な端末（`html.no-glass`）では回さない——静止した枠だけで「進行中」は伝わる。器は DOM の実体が要るので `setNowRing()` が付け外しするが、**既にあるときは作り直さない**（1 分ごとの `updateNowMarker()` で回転が先頭へ戻る）。
- **アイコン**: 絵文字は使わず **SVG（Lucide系）**。`ICONS` レジストリ + `icon(name, cls)` ヘルパ（`index.html`）。静的箇所（ボトムナビ・FAB・モーダル閉じる）はインラインSVG。
- **画像と転送量（会場の細い回線が前提）**: 自前のコードは軽い（`index.html` は gzip 53KB、
  イベント JSON は 8.6KB）ので、**転送量のほぼ全部は画像と外部リソース**。ここを増やさない。
  ①**告知バナーを原寸のままリポジトリに置かない**——表示枠は `w-full aspect-[2/1] max-h-72` で
  最大 672×288 CSS px しかない。`scripts/optimize_images.py` が幅 1400px へ縮小し、現行イベントは
  WebP、終了済みイベントは**同名 PNG のまま 256 色へ量子化**して書き出す（終了済みの JSON を
  編集しない規約を守るため拡張子を変えられない）。元画像は再生成のためリポジトリに残すが配信はしない。
  ②**書影は `coverUrl(url, px)` を通す**（ホスト判定は前方一致で書かない。`endsWith("toyokan.co.jp")` は
  `eviltoyokan.co.jp` を拾う）——JSON にはフルサイズ（`width=1200` / `_SL1500_` /
  `LZZZZZZZ`）の URL が入っているが表示枠は 64×96 px。描画時に小さい派生へ付け替えるので
  **JSON は書き換えない**。未知のホスト・想定外の形は素通しし、派生が 404 のときは
  `renderBooks()` が元 URL で 1 回だけ retry してからプレースホルダーに落ちる（外部 CDN の
  パラメータ仕様に賭けない）。③新しい `<img>` には `loading="lazy"` と**箱の確保**を必ず付ける。
  バナーの実寸はイベントごとに違う（1400×685 と 1400×788）ので、汎用シェルに `width`/`height` の
  数値は持てない——`aspect-[2/1]` で比率だけ固定する。会場マップ（`#venueMap`）も同様に実寸が
  一定しないので `aspect-square object-contain`（現行 2 枚は 1349×1459 / 1529×1625 とほぼ 1:1。
  比率が違っても歪まず、余白は地の色になる）。**`loading="lazy"` の画像を「読み込めるまで隠す」
  作りにしてはいけない**——`display:none` の間はビューポートに入りようがないので取得自体が
  始まらず、`load` が永久に来ない＝画像が二度と出ない。隠すのは `error` のときだけにして、
  ちらつきは箱の先取りで受ける。④`<head>` のフォント CSS は
  `media="print"` → `onload` で `all` に戻す形にして**描画をブロックさせない**（`display=swap` と
  併せて本文は即出る）。接続確立が高くつくので `preconnect`（フォント・Tailwind）と
  `dns-prefetch`（画像ホスト）を置くが、preconnect は張りすぎると逆効果なので増やさない。
  なお **Tailwind Play CDN（約120KB gzip ＋実行時 JIT）が初回表示の最大のボトルネック**で、
  同じ設定からローカルビルドすると 26KB まで落ちる。ビルド工程なしを優先して CDN のままにしてあるので、
  やるなら生成物をコミットする方式（`build_fuseneko.py` と同じ作法）にすること。
